멀티에이전트로 combat/balance, UI/렌더링, save/data 세 영역을 리뷰해서 나온 내용. 버그로 확정된 건(#10~12) 위에서 이미 수정 완료했고, 여기는 판단이 필요하거나 다음 작업(특히 #7 스킬 시스템) 전에 미리 알아두면 좋을 것들.

### Combat / Balance
- **기절·약화가 앞 몬스터에만 적용됨**: `combatSystem.js`의 `stunChance`/`weakenChance` 트레잇은 `combat.monsterAttackElapsedMs`/`monsterNextHitReductionPct`(맨 앞 몬스터 전용 필드)만 건드리고, 스택된 `extraEnemies`는 전혀 영향을 못 받음. 처치가 늦어져서 몬스터가 쌓일수록(정확히 그럴 때일수록) 이 트레잇들의 체감 효과가 옅어짐. 스킬 시스템의 `stunAll`은 이미 스택 전체를 고려하도록 설계했지만(SkillSystemDesign.md #3), 기존 패시브 트레잇도 같이 손볼지는 결정 필요.
- **오프라인 안전 판정이 몬스터 스택을 아예 모름**: `offlineSettlement.js`의 `isSafeAgainst()`는 몬스터 1마리 기준으로만 계산함. 처치 시간이 스택 간격(6초, `MONSTER_BALANCE.stackSpawnIntervalMs`)보다 길면 실시간에서는 이미 2~3마리가 쌓였을 상황인데, 오프라인 시뮬레이션은 "안전"으로 판단할 수 있음 - 근본적으로 다시 설계하기보다는, 최소한 안전 마진(`SAFETY_MARGIN`)을 좀 더 보수적으로 낮추는 정도의 완화책을 검토해볼 만함.
- **성장 곡선 확인 필요**: 몬스터 `hpGrowth(1.12)`와 `attackGrowth(1.10)`가 동시에 복리로 커지는데 `attackIntervalMs`는 레벨에 안 따라 고정임 - 대략 레벨당 받는 피해 기대치가 ~1.23배씩 복리로 늘어나는 셈이라, 플레이어 스탯 성장(힘/지력 +2%/포인트, 제곱근 곡선으로 레벨 게이트)이 이걸 못 따라가는 구간이 있는지 스프레드시트로 한번 확인해볼 가치 있음. (기존 #3과 동일 항목, 근거만 구체화됨)

### UI / 렌더링 (다음 스킬바 작업 전에 특히 참고)
- **지금 있는 🔥🛡️🏹 목업 버튼은 껍데기뿐**: `renderer.js`의 control-bar 버튼들은 CSS 클래스 토글 말고 아무 로직도 없음(`onStyleSelect` 같은 콜백조차 안 연결됨) - 스킬바 만들 때 "확장"이 아니라 "교체" 대상으로 봐야 함.
- **컨트롤바 CSS가 쿨다운 UI를 못 담음**: `.ctrl-btn`이 텍스트만 중앙에 박힌 단순 원형이라, 쿨다운 표시(오버레이/숫자 카운트다운)를 넣으려면 버튼 내부 구조(아이콘+오버레이+라벨)를 새로 짜야 함.
- **3열은 스크롤이 아니라 "잘림"**: `overflow:hidden`이라 내용이 늘어나면 스크롤바 없이 그냥 잘려서 안 보임(경고도 없음). 이번 세션에 여러 번 겪었던 문제라 스킬 관련 UI를 3열에 추가하면 또 튜닝이 필요할 가능성 높음.
- **스킬 선택 모달은 아직 오버플로우 방지가 없음**: `.modal-box`에 `max-height`/`overflow-y:auto`가 없어서, 후보가 여러 개인 스킬 선택 모달을 그대로 얹으면 짧은 화면에서 위아래로 잘릴 수 있음 - 지금까지의 모달(텍스트/텍스트영역 위주)은 짧아서 문제된 적이 없었을 뿐.
- **`title` 툴팁 패턴 재검토**: 스탯/영구강화 설명을 마우스오버 툴팁으로 숨긴 패턴을 스킬 설명에도 그대로 쓸지 - 터치 기기에서 안 먹히고 시각적 힌트가 전혀 없다는 단점을 감안해서 의도적으로 결정할 것.

### Save / Data
- **v6 마이그레이션 작성 시 참고할 기존 패턴 3가지** (`saveManager.js`): ① `activeStyleId`처럼 "허용 목록에 있는 값만 통과"(무기/마법 검증에 그대로 적용), ② `extraEnemies`처럼 "배열 원소 하나하나 유효성 검사 후 필터"(`skillCooldowns`/`unlockedSkillIds`에 적용), ③ `character.mastery`처럼 "정적 설정을 순회하며 그 키만 골라오기"(마스터리 타입별 `unlockedSkillIds` 객체에 적합).
- **v6은 처음으로 진짜 구조 변경이 필요한 마이그레이션**: 지금까지 `migrate()`는 버전 번호만 올리는 빈 함수였고 실제 필드 이전은 `normalizeState`에서 즉석으로 처리했음. `activeStyleId` → `activeWeaponId`/`activeMagicId` 분리는 실질적인 리네임이라 `migrate()`가 처음으로 진짜 일을 해야 할 수도 있음.
- **쿨다운/버프 잔여시간은 마이그레이션 시 리셋 권장**: v4→v5가 기존 스탯 진행도를 안 이어받은 것과 같은 맥락 - 구버전 세이브의 스킬 쿨다운/버프 타이머는 의미가 없으므로 0/빈 값으로 시작하는 게 맞음.
- **두 개의 rAF 루프**: 게임 루프(`gameLoop.js`)와 캔버스 렌더러(`battlefieldCanvas.js`)가 독립적으로 도는데, 캔버스 쪽은 `state`를 직접 안 건드리고 `setSnapshot`으로만 받아서 지금은 안전함. 다만 탭이 백그라운드에서 돌아오면 누적된 틱을 한꺼번에 처리(catch-up)하면서 `handleCombatEvent`가 한 프레임 안에 여러 번 불릴 수 있는데, 스킬 시전 이펙트(파티클 등)가 늘어나면 이게 한꺼번에 몰려 보일 수 있음.
