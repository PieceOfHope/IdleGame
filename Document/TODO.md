## 🖥️ 레이아웃 / UI

### 4. 프레임을 3단 구성으로 재편
- 지금은 좌(전투 화면) / 우(스탯·숙련도·영구강화, 자체 스크롤)의 2단 구조.
- **질문**: 3단으로 나눌 때, 우측 패널(스탯/숙련도/영구강화)을 두 칼럼으로 쪼개는 것인지, 아니면 완전히 새로운 콘텐츠(인벤토리, 파티/아군 정보, 로그 전용 칼럼 등)가 3번째 칼럼으로 추가되는 것인지 확인 필요.
- **내 의견**: 만약 스탯/숙련도가 항목 수 대비 세로로 너무 길어서 스크롤이 잦다면, "스탯+숙련도" / "영구강화" 를 별도 칼럼으로 쪼개는 게 자연스러워 보임.

### 5. "몬스터 Lv.N" 대신 "현재 스테이지" 표시
- 현행: `몬스터 Lv.22 · 파밍 중` 처럼 몬스터 레벨을 그대로 노출.
- **내 의견**: 예전에 논의했던 "스테이지당 5웨이브" 아이디어와 엮으면, 표시만 바꾸는 방법(예: `스테이지 = (몬스터레벨 - 1) / 5 + 1`로 파생 계산)과, 웨이브 시스템을 실제로 붙이면서 상태에 별도 `stage` 카운터를 추가하는 방법 두 가지가 있음. 후자를 염두에 두고 있다면 웨이브 시스템 설계를 먼저 확정하는 게 순서상 맞음.

## 🧬 시스템 개편 (규모가 큰 작업들)

### 6. 디아블로2 스타일 스탯 포인트 분배
- 요청: 캐릭터 레벨업 시 스탯 포인트 5개 지급 → 힘/민첩성/지력/체력/회복력에 자유 배분, 재분배(내리기)도 가능.
- 현재 구조와의 충돌: 지금 스탯은 "사용 횟수 기반 자동 레벨업"(무기를 쓸수록 힘이 오르는 식, `characterSystem.js`)이라 애초에 "캐릭터 레벨"이라는 개념 자체가 없음.
- **내 의견**: 전면 교체보다는, 숙련도(무기/마법)는 지금처럼 사용 기반으로 두고, 기본 스탯 5종만 레벨업 포인트 배분제로 바꾸는 하이브리드가 기존 구조를 덜 건드리면서 요청을 만족시킬 수 있음. "캐릭터 레벨/경험치"를 어떻게 정의할지(예: 총 몬스터 처치 수 기반?)부터 다음에 정해야 함.

### 7. 무기 + 마법 조합(로드아웃) 시스템
- 요청: 무기 종류 1개 + 마법 종류 1개를 동시에 선택해서 조합, 선택한 것들의 숙련도만 계속 성장.
- 현재 구조: `activeStyleId` 하나만 선택 가능(무기/마법 구분 없이 8종 중 1개 - `combatSystem.js`).
- **내 의견**: `MASTERY_CONFIG`에 이미 `category`(physical/magic) 필드가 있어서, "physical 슬롯 1개 + magic 슬롯 1개"의 이중 슬롯 구조로 바꾸는 게 자연스러움. 다만 공격 판정을 어떻게 할지(매 공격마다 무기+마법 데미지 동시 적용? 번갈아 발동?) 전투 로직 설계가 필요.

### 8. 영구 강화 - 캐릭터 레벨에 따른 순차 해금
- 요청: 영구 강화 항목들이 캐릭터 레벨에 따라 순차적으로 해금.
- 현재 구조: `PERMANENT_UPGRADE_CONFIG` 3개 항목이 처음부터 전부 열려 있음.
- **내 의견**: 레거시 업그레이드 시스템(`upgradeConfig`)에 이미 `requiresUpgrade.level` 락 패턴이 있어서, 같은 방식을 영구강화 쪽에 추가하는 건 구조적으로 어렵지 않음. 다만 이것도 "캐릭터 레벨" 개념이 먼저 있어야 해서 #6과 연결됨.
